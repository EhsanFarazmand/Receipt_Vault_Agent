# Deployment — Receipt Vault

Receipt Vault is **local-first**: it needs no cloud to run (see the root `README.md`
Quickstart). This folder documents the **optional** Cloud Run deployment shown in the
video (course concept: *Deployability*). The competition does **not** require a live
public endpoint — a documented, reproducible local repo is sufficient.

---

## Option A — Local-first (default, recommended for the demo)

```bash
uv sync
uv run python scripts/seed_demo.py         # populate the demo ledger
uv run adk web                             # or: agents-cli playground
uv run python scripts/daily_watchdog.py    # the standing-watch sweep
```

Register the daily sweep with your OS scheduler so the agent keeps watch (snippets are
in `scripts/daily_watchdog.py`: Windows Task Scheduler / cron).

---

## Option B — Cloud Run (optional, headless)

The authentic Terraform, CI/CD, and service account wiring are best generated by the
CLI so they match your `agents-cli` version. From the repo root:

```bash
# 1. Add Cloud Run deployment scaffolding (Terraform, service account, service.tf).
agents-cli scaffold enhance . --deployment-target cloud_run --agent-directory app \
  --agent-guidance-filename CLAUDE.md

# 2. (Optional) add a CI/CD runner — you'll be asked GitHub Actions vs Cloud Build.
agents-cli scaffold enhance . --cicd-runner github_actions

# 3. Provision infra + deploy (requires GCP auth; deploy needs explicit approval).
agents-cli login --interactive
agents-cli deploy
```

This repo already ships a working `Dockerfile` and `app/fast_api_app.py` so a manual
`gcloud run deploy` also works:

```bash
gcloud run deploy receipt-vault \
  --source . \
  --region us-central1 \
  --set-env-vars GOOGLE_GENAI_USE_VERTEXAI=TRUE,GOOGLE_CLOUD_LOCATION=us-central1
```

> **Secrets:** never bake keys into the image. On Cloud Run, use **Secret Manager**
> (`--set-secrets`) or Vertex AI (workload identity) rather than a `GOOGLE_API_KEY`
> env var. `.env` is git-ignored and never copied into the container.

### Session storage
In-memory sessions are fine for the demo. For persistent sessions, re-scaffold with
`--session-type cloud_sql` (Postgres 15, IAM auth) — see the deploy skill.

## The daily Watchdog on Cloud Run (ambient / scheduled agent)

`app/fast_api_app.py` enables the Pub/Sub trigger endpoint
(`/apps/app/trigger/pubsub`). Wire the daily sweep with Cloud Scheduler → Pub/Sub —
no custom scheduling code:

```bash
# A topic the scheduler publishes to, connected to the agent's pubsub trigger.
gcloud pubsub topics create receipt-vault-daily

gcloud scheduler jobs create pubsub receipt-vault-daily-sweep \
  --schedule "0 20 * * *" \        # 8 PM daily
  --topic receipt-vault-daily \
  --message-body '{"prompt":"Run today watchdog sweep and report the most time-sensitive item."}' \
  --time-zone "America/Los_Angeles"
```

Cloud Run/GKE (not Agent Runtime) are required for scheduled/event triggers.
Route the ambient output to Cloud Logging / an alert, since there is no interactive user.
